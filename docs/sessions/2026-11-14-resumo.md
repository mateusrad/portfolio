## Decisões técnicas e por quê

- **Subdomínio do próprio repositório `portfolio`**: o demo continua em
  `mateusrad.github.io/demo-lancamento-imobiliario`, porque o domínio vale
  só para este repositório. O arquivo `CNAME` na raiz não pode ser apagado,
  senão o site volta para o endereço antigo.
- **`.gitattributes` com `*.vcf -text`**: o resumo de 2026-10-16 dizia que
  o vCard estava em CRLF, mas o `core.autocrlf=true` o gravava em LF no
  repositório, e o Pages servia LF. O padrão vCard exige CRLF.
- **Edições com `sed -b` no Git Bash**: o `sed -i` comum do Git Bash (msys)
  remove os `\r` silenciosamente. O `-b` preserva os bytes.
- **Mensagem diferente em cada link do WhatsApp**: para o Mateus saber se o
  contato veio do site ou do cartão.
- **Assinaturas apontam para o cartão, e não para a home**: quem clica quer
  falar com o desenvolvedor, e o cartão entrega isso em uma tela. O cartão
  foi tornado indexável para que esses links continuem ajudando no Google.
  O marcador de origem (`cartao.html?origem=site`) ficou para depois, se o
  Mateus sentir falta de saber de onde veio o contato.
- **Verificação visual com Chrome headless**: o painel de navegador abre os
  arquivos locais como `data:`, sem o CSS. O Chrome headless, com
  `--screenshot`, funciona.
- **IA no WhatsApp (ideia futura)**: só com a WhatsApp Cloud API oficial.
  APIs não oficiais (Evolution, Baileys) podem fazer o número ser banido.
  Detalhes em "Pendências".

## Problemas resolvidos

- O vCard era publicado em LF por causa do `core.autocrlf` (corrigido com o
  `.gitattributes`).
- O "Enforce HTTPS" aparecia indisponível com o certificado já aprovado
  (atraso da interface; ligado pela API).
- O computador local guardou o "domínio não existe" da primeira consulta
  (cache negativo). O teste foi feito com `curl --resolve`, e para o
  navegador basta `ipconfig /flushdns`.
- Erro "item não localizado" no catálogo pelo celular: provavelmente o campo
  obrigatório "País de origem", que só aparece no app do PC. No PC, salvou.
